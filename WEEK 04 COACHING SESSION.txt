When a user submits a form, the browser packages up all the input values and sends them inside the **HTTP request body**. 

Express makes those values available inside `req.body`. Using `const { name, description, contactEmail } = req.body;` is a JavaScript feature called **destructuring**. It extracts just those specific properties out of `req.body` into clean individual variables so you can easily pass them into your `createOrganization(...)` function.

const flashMiddleware = (req, res, next) => {
    /**
- The flash function handles both setting and getting messages
- Called with 2 args (type, message): stores a new message
- Called with 1 arg (type): retrieves and clears messages of that type
- Called with 0 args: retrieves and clears all messages
     */
    req.flash = function(type, message) {
        // Initialize flash storage if it doesn't exist
        if (!req.session.flash) {
            req.session.flash = {
                success: [],
                error: [],
                warning: [],
                info: []
            };
        }

        // SETTING: Two arguments means we're storing a new message
        if (type && message) {
            // Ensure this message type's array exists
            if (!req.session.flash[type]) {
                req.session.flash[type] = [];
            }
            // Add the message to the appropriate type array
            req.session.flash[type].push(message);
            return;
        }

        // GETTING ONE TYPE: One argument means retrieve messages of that type
        if (type && !message) {
            const messages = req.session.flash[type] || [];
            // Clear this type's messages after retrieving
            req.session.flash[type] = [];
            return messages;
        }

        // GETTING ALL: No arguments means retrieve all message types
        const allMessages = req.session.flash || {
            success: [],
            error: [],
            warning: [],
            info: []
        };

        // Clear all flash messages after retrieving
        req.session.flash = {
            success: [],
            error: [],
            warning: [],
            info: []
        };

        return allMessages;
    };

    next();
}

That is a fantastic custom middleware implementation of flash messages!

Looking at how you store messages on `req.session.flash` and then clear them when retrieved: **What is the main benefit of storing these flash messages in the session instead of just passing them directly into `res.render()`?**

[ILEGUBO OWUSU]:
I think storing them in session give us a little more control on how to when to display the flash messages. In that, if the user enters data and submits, a flash message is displayed on the screen and we are able to clear the flash message from the session immediately so that when the user refreshes the page, the flash message is no longer displayed again.

[COACH]:
You nailed it! That is the exact reason. 

Because HTTP requests are stateless, a traditional `res.redirect()` causes the browser to make a completely new request. If you tried to use standard variables, they'd be lost during that redirect. Storing messages in `req.session` keeps them alive across the redirect, and clearing them immediately upon retrieval ensures they disappear after a single page view so refreshing doesn't show stale alerts.
