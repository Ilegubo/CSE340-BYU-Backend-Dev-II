================================================================================
TOPIC: Express-Validator Architecture, Request Pipeline & Validation Layers
================================================================================

QUESTION ASKED:
--------------------------------------------------------------------------------
"What is the use of the body validation in 'organizationValidation' if 
validationResult(req) is used to validate incoming data in 'processNeworganizationForm' 
and 'processEditOrganizationForm'? Also, how does organizationValidation receive 
the name, description and contact email when called in the post request in router.js. 
I do understand how the code is supposed to validate incoming info at the parts 
of the code base where they have been declared and implemented. However considering 
all the various places where the validations are being called, I do not understand 
how they are supposed to work with each other and more importantly, why there are 
so many validations and error checkers at several points during the code. 
They seem redundant to me."
--------------------------------------------------------------------------------

RESPONSE:
--------------------------------------------------------------------------------

1. WHAT DOES 'organizationValidation' DO vs 'validationResult(req)'?
================================================================================
They are not doing the same thing. In fact, 'validationResult(req)' does NOT 
validate anything on its own!

* organizationValidation is the "INSPECTOR":
  In src/controllers/organizations.js:
  - 'body('name').notEmpty().isLength(...)' runs the actual test suite.
  - It examines req.body.name, trims whitespace, verifies character limits, etc.
  - If a rule fails, it silently attaches an error object internally to the 
    incoming 'req' object.
  - Crucially: It DOES NOT stop or redirect the request; it tags errors and 
    calls next() so Express continues to the next step.

* validationResult(req) is the "REPORTER":
  In processNewOrganizationForm / processEditOrganizationForm:
  - 'validationResult(req)' simply asks: "Did the inspector 
    (organizationValidation) attach any errors to this request?"
  - If you remove organizationValidation, validationResult(req) will ALWAYS 
    return that there are zero errors, because no rules were ever executed.


2. HOW DOES 'organizationValidation' RECEIVE FORM DATA IN router.js?
================================================================================
Express routes execute middleware sequentially from left to right.

Route definition in src/routes.js:
router.post('/edit-organization/:id', organizationValidation, processEditOrganizationForm);

Here is the step-by-step lifecycle flow:

+------------------------------------------------------------------------------+
| 1. BROWSER: User clicks "Submit"                                             |
|    Browser sends an HTTP POST request containing form fields:                |
|    name="BrightFuture"&description="Nonprofit..."&contactEmail="info@org.com"|
+------------------------------------------------------------------------------+
                                       |
                                       v
+------------------------------------------------------------------------------+
| 2. SERVER.JS: express.urlencoded({ extended: true })                         |
|    Parses the raw HTTP body text into a clean JavaScript object:             |
|    req.body = {                                                              |
|        name: "BrightFuture",                                                 |
|        description: "Nonprofit...",                                          |
|        contactEmail: "info@org.com"                                          |
|    };                                                                        |
+------------------------------------------------------------------------------+
                                       |
                                       v
+------------------------------------------------------------------------------+
| 3. ROUTES.JS: Middleware 1 -> organizationValidation                         |
|    - Each body('field') function reads req.body[field].                      |
|    - Checks rules (notEmpty, trim, isEmail, max length).                     |
|    - If any fail, records errors internally on `req`.                        |
|    - Calls next() to advance to the controller handler.                      |
+------------------------------------------------------------------------------+
                                       |
                                       v
+------------------------------------------------------------------------------+
| 4. CONTROLLER: Middleware 2 -> processEditOrganizationForm                   |
|    - Calls validationResult(req) to inspect the recorded errors.             |
|    - IF errors exist:                                                        |
|         Flash error messages to session and redirect back to form.           |
|    - IF valid (no errors):                                                   |
|         Proceed to run database UPDATE query and save the record.            |
+------------------------------------------------------------------------------+


3. WHY ARE THERE VALIDATIONS AT SO MANY POINTS? (DEFENSE IN DEPTH)
================================================================================
While it may seem redundant, web applications use a 3-tier safety model called 
"Defense in Depth". Each layer protects against a different failure mode:

+-------------------+-----------------------------+----------------------------+
| LAYER             | WHERE IT LIVES              | PURPOSE & RESPONSIBILITY   |
+-------------------+-----------------------------+----------------------------+
| 1. Client-Side    | HTML / EJS templates        | Immediate User Experience: |
|                   | (required, maxlength,       | Gives instant browser      |
|                   |  type="email")              | warnings without a slow    |
|                   |                             | network round trip.        |
|                   |                             | Easily bypassed via        |
|                   |                             | DevTools/Postman!          |
+-------------------+-----------------------------+----------------------------+
| 2. Server-Side    | organizationValidation      | Business Rules & Security: |
|                   | + validationResult(req)     | Validates & sanitizes all  |
|                   | in controllers/routes       | incoming data before it    |
|                   |                             | can execute queries or     |
|                   |                             | crash the application.     |
+-------------------+-----------------------------+----------------------------+
| 3. Database       | PostgreSQL setup.sql        | Ultimate Integrity:        |
|                   | (NOT NULL, VARCHAR(150),    | The final safety net.      |
|                   |  FOREIGN KEY)               | Prevents data corruption   |
|                   |                             | even if a backend script   |
|                   |                             | has bugs or runs raw SQL.  |
+-------------------+-----------------------------+----------------------------+

SUMMARY:
--------
- HTML tags protect the user from accidental typing mistakes.
- organizationValidation protects the server from malicious or malformed data.
- validationResult(req) gives the controller control over the user response flow.
- Database constraints protect your persistent storage from corruption.
